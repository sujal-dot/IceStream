# IceStream Event Schema Documentation

This document defines the baseline schema for checkout telemetry events generated by the IceStream generator and consumed across the IceStream observability platform.

## Checkout Event Schema (`checkout-events` topic)

### Baseline Schema Definition

| Field | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `event_id` | string | yes | Unique event identifier | `"evt_8f3a9b1c2d4e5f60"` |
| `event_time` | timestamp | yes | Timezone-aware UTC event time (ISO 8601 with ms) | `"2026-08-14T05:15:21.123Z"` |
| `event_type` | string | yes | Event category indicator | `"checkout"` |
| `customer_id` | string | yes | Unique customer identifier | `"CUS000102"` |
| `session_id` | string | yes | Checkout web session identifier | `"SES881920"` |
| `order_id` | string | yes | Order transaction identifier | `"ORD9918273"` |
| `product_id` | string | yes | Product catalog SKU identifier | `"PROD003"` |
| `quantity` | integer | yes | Quantity purchased (1–5) | `2` |
| `unit_price` | number | yes | Product unit price in local currency | `2990.00` |
| `amount` | number | yes | Total checkout price (`quantity × unit_price`) | `5980.00` |
| `currency` | string | yes | ISO 4217 Currency code | `"INR"` |
| `payment_method` | string | yes | Payment option (`UPI`, `CREDIT_CARD`, `DEBIT_CARD`, `NET_BANKING`, `WALLET`, `COD`) | `"UPI"` |
| `payment_status` | string | yes | Transaction status (`SUCCESS`, `FAILED`, `PENDING`) | `"SUCCESS"` |
| `device` | string | yes | Originating device category (`mobile`, `desktop`, `tablet`) | `"mobile"` |
| `country` | string | yes | ISO 3166-1 alpha-2 country code | `"IN"` |
| `source` | string | yes | Event source system identifier | `"web"` |
| `source_version` | string | yes | Producer schema version | `"v1"` |

---

## Controlled Schema Corruption & Anomaly Injection

For testing real-time stream quality, quarantine, and circuit-breaking capabilities, the event generator supports controlled error injection via `--error-rate <percentage>` and `--error-types`.

Injected errors alter valid baseline payloads by applying **exactly one primary anomaly type** without adding synthetic diagnostic tags (such as `"is_bad": true`).

### Supported Injected Error Types

| Error Type Key | Description | Example Payload Difference |
| :--- | :--- | :--- |
| `null_amount` | Replaces numerical amount with JSON `null`. | `"amount": null` |
| `null_customer_id` | Replaces customer identifier with JSON `null`. | `"customer_id": null` |
| `negative_amount` | Mutates numerical amount to a negative float value. | `"amount": -5980.00` |
| `duplicate_event_id` | Emits a second event reusing an exact previous `event_id`. | Reuses `"event_id": "evt_8f3a9b1c2d4e5f60"` |
| `invalid_currency` | Replaces valid currency code with an invalid string. | `"currency": "XXX"` |
| `missing_required_field` | Completely deletes a mandatory field key from JSON object. | Field `"customer_id"` key omitted entirely |
| `wrong_data_type` | Converts numeric fields to incompatible string types. | `"quantity": "two"` or `"amount": "5980.00"` |
| `future_timestamp` | Sets `event_time` to +1 hour ahead of current UTC time. | `"event_time": "2026-08-14T06:15:21.123Z"` |
