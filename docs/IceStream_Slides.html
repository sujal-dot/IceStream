Data Integrity Engine

Deep Dive: Multi-Vector Quality & Schema Drift Detection

Blending ultra-fast streaming validation with enterprise declarative data contracts.

⚡ 7 In-Stream Anomaly Detectors

  • Null & Required Checks: Enforces mandatory customer_id, order_id, amount without crashing.
  • Positive Amount & Currencies: Rejects negative amounts; validates ISO currencies (USD, EUR, GBP).
  • Impossible Amount Bounds: Catches outlier transaction spikes and rogue orders.
  • Timestamp Drift & Lateness: Rejects future-dated clocks and excessively late events.
  • Rolling Deduplication: In-memory windowed deduplication over event IDs and order numbers.
  • Granular Severities: CRITICAL, HIGH, MEDIUM, LOW tiers drive targeted circuit responses.

🧬 Schema Drift & Great Expectations

  • Zero-I/O Dynamic Comparator: Evaluates payload structures against cached JSON schemas in < 0.4 ms.
  • Change Taxonomy: Classifies NEW_COLUMN, MISSING_COLUMN, TYPE_CHANGE, RENAMED_COLUMN.
  • Compatibility Engine: Evaluates changes as COMPATIBLE, WARNING, or BREAKING.
  • Great Expectations v0.18: Standardizes batch expectation results into streaming ValidationResult.
  • Event Deduplication: Multiple rule failures on 1 record are counted as 1 failed event to prevent skew.
  • Prometheus Exporters: Real-time low-cardinality rule metric counters.
Autonomous Remediation

Dynamic Circuit Breaker & 11-State Self-Healing Pipeline

Moving data engineering from passive Slack alerts to closed-loop, automated failure isolation and self-healing.

🔄 The 11-State Self-Healing FSM

  • RUNNING: Baseline healthy operation (Error rate < 1.0%).
  • DEGRADED: Warning threshold crossed (1.0% - 2.0%). Early alerts fired.
  • CIRCUIT_OPEN: Critical threshold breached (> 2.0%). Ingestion tripped.
  • QUARANTINING: Corrupted events routed to Iceberg DLQ; Silver stream paused.
  • REMEDIATING: Controller acquires PostgreSQL idempotency lock.
  • REFETCHING: Re-fetches clean payloads from upstream source adapters.
  • REPROCESSING: Re-runs Quality Engine against re-fetched events.
  • VALIDATING: Confirms 0 violations across recovered batch.
  • RESUMING: Half-Open probe verifies source stability.
  • RECOVERED: Restored to RUNNING; incident auto-resolved in Slack.

📊 Rolling Error-Rate Engine

  • Calculates dynamic ratio: failed_events / total_events.
  • 1m & 5m dual rolling windows eliminate false tripping from momentary spikes.

🔒 Half-Open Recovery Probe

  • Controlled single-probe mechanism prevents flapping pipelines.
  • Requires verified zero-error batch before full circuit closure.

🛡 Idempotent Concurrency Lock

  • PostgreSQL-backed state manager with SQLite resilient fallback.
  • Max 3 attempts with exponential backoff prevents retry storms.
Lakehouse Storage

Apache Iceberg Lakehouse: Multi-Tiered ACID Architecture

Stateless REST catalog, snapshot isolation, and elimination of the streaming small-file problem.

📂 Multi-Tiered Separation

  • Bronze Table: Raw immutable event log preserving original payloads for audit.
  • Silver Table: Curated, schema-enforced, clean data for analytics and BI.
  • Quarantine Table: Dedicated ACID Dead Letter Queue for corrupted records.

⚡ Optimistic Concurrency Control (OCC)

  • Zero Reader Blocking: Readers never block writers via snapshot isolation.
  • Atomic Pointer Swaps: REST Catalog commits table metadata atomically.
  • Durability Proven: Audited under 500 concurrent write collisions with 0 failures.

🗜 Small-File Problem Eliminated

  • 10s Flink checkpoint alignment balances low latency with file size.
  • Micro-batch QuarantineWriter (50-event / 5s buffer) prevents S3 file clutter.
  • Automated background compaction merges small files into 128 MB blocks.
